Wii U 3D Graphics & Game Engine (C++20)

Framework modular de videojuegos 3D en C++20 diseñado para Nintendo Wii U (Aroma) sin SDL2 en consola, aprovechando la CPU tri-núcleo IBM Espresso (1.24 GHz), la GPU AMD Latte R700 / GX2 (550 MHz) y audio nativo sndcore2 / AX, con arquitectura multi-consola (Wii U / Switch / PC).

8/8 Suites Gráficas Validadas en Wii U Real 43/43 Pruebas Automáticas 8 Librerías Estáticas (DAG) Zero-Alloc 60 FPS Licencia Apache 2.0

1. Lo Básico y Compilación Rápida

El motor utiliza devkitPro / WUT y CMake para compilar de forma desacoplada tanto la librería del framework (build_lib/) como el paquete ejecutable build/wiiu_demos.wuhb listo para Cemu o consola física Wii U.

Hardware Objetivo

IBM Espresso PPC 750CL Tri-Core @ 1.24 GHz, AMD Latte R700 @ 550 MHz, 32 MB eDRAM (MEM1) y 2 GB DDR3 (MEM2).

Umbrella Header

Incluye #include <WiiUEngine.hpp> y enlaza engine_framework para usar el motor en cualquier juego.

Invariantes Críticos

0 símbolos SDL_ en Wii U, 0 CRLF, Zero-Alloc en bucles a 60 FPS y guardas ProcUI en todo GX2DrawDone().

Comandos de verificación y compilación

# 1. Validar terminaciones LF, higiene de cabeceras e invariantes GX2
python scripts/agent_harness.py check

# 2. Compilar demo (.wuhb / .rpx) y librería estática (engine_framework)
python scripts/agent_harness.py build --lib

# 3. Transferir por FTP a Wii U real (reemplaza la IP por la de tu consola)
curl.exe -T build/wiiu_demos.wuhb ftp://192.168.0.140:21/fs/vol/external01/wiiu/apps/wiiu_demos.wuhb

4. Ejemplos de Uso (C++20)

A. Arrancar una escena propia con el framework

#include <WiiUEngine.hpp>

class MiEscena final : public WiiU::GameScene3D {
public:
    void OnEnter() override {
        GameScene3D::OnEnter();
        WiiU::Graphics::ProceduralMeshBuilder::CreateUVSphere(m_esfera, 1.0f, 16, 12, 0.2f, 0.8f, 1.0f);
    }
    void OnRender3D(const WiiU::Matrix4x4& view, const WiiU::Matrix4x4& proj) override {
        auto& r = WiiU::ForwardRendererGX2::Instance();
        r.SetViewProjection(proj * view, GetCameraPosition());
        WiiU::MaterialPropertyBlock mat{};
        mat.ubo.pbrParams[0] = 0.25f; // Roughness
        mat.ubo.pbrParams[1] = 0.85f; // Metallic
        r.RenderStaticMeshPBR(m_esfera, WiiU::Matrix4x4::Identity(), mat, 0u);
    }
    void OnExit() override {
        m_esfera.Destroy();
        GameScene3D::OnExit();
    }
private:
    WiiU::StaticMesh m_esfera;
};

int main() {
    WiiU::Engine engine;
    if (engine.Init(std::make_unique<MiEscena>())) {
        engine.Run();
    }
    return 0;
}

5. Errores Conocidos y Limitaciones de Silicio

1. RenderSkinnedMeshInstanced en Nintendo Wii U real

El camino multi-instancia de skinning (bird_orange.wmesh + RenderSkinnedMeshInstanced) produjo congelamiento en el primer frame en consola física durante las pruebas de G6. El Hardware Instancing estático (RenderStaticMeshInstanced con Ring Buffer lock-free) opera estable a 55 FPS; el skinning multi-instancia queda pendiente de auditoría específica en silicio real.

2. Instrucción R600 CUBE (samplerCube) en CafeGLSL y Cemu 2.6

Compilar samplerCube con CafeGLSL genera microcódigo con artefactos radiales en Cemu 2.6 Vulkan y riesgos en cubemaps lineales en Latte. Solución adoptada: usar Atlas 2D 3×2 (SampleCubeAtlas()) o reflexión hemisférica analítica.

3. Escalón VSync 60→30 Hz y presión de GPRs en pbr_mesh_gx2.frag

El uber-shader PBR actual (36 GPRs, 10 modos) reduce la ocupación de wavefronts en AMD Latte R700. Con VSync ON, cualquier escena que supere 16.67 ms cae a 30 FPS exactos (ej. G2 rinde 32 FPS con VSync OFF en fillrate puro). Dividir el uber-shader en variantes especializadas devolverá 60 FPS sostenidos con VSync.

4. Límites físicos de Ray Tracing GPU en Wii U (Suite G8)

AMD Latte (~0.35 TFLOPS) no posee RT Cores. G8 demuestra BVH Stackless Zero-Alloc y Render Scale dinámico: mantiene 30 FPS hasta 540p y baja a ~20–25 FPS a 720p de cerca. Para juegos completos en Wii U, la vía recomendada es rasterización (G1–G7) + BVH en CPU para física/IA.
